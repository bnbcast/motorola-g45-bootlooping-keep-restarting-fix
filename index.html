The Problem

Your Moto G45 5G reboots every ~2 minutes. Factory resets and firmware flashes don't help. Here's why — in plain English.

Symptom: The 2-Minute Bootloop

Phone boots, works for ~2 minutes, then reboots. Repeats forever. Survives OTA updates, LMSA firmware flashes, and factory resets.

Root Cause: Corrupt Modem NV

The modem's non-volatile memory (modemst1/modemst2) is corrupted. On every boot the modem asserts, QMI services vanish, and the RIL daemon qcrilNrd dereferences a dead token (0xffffffffffffff02 = -254) → SIGSEGV → watchdog reboot.

Why Other Fixes Failed

  • Firmware flashes (OTA/LMSA) never touch modemst1/2
  • Factory reset only masks it for ~3 hours (re-provisions modem stack)
  • Disabling apps reduces crash rate but doesn't fix the modem
  • Custom ROMs can't fix it — they don't touch modem partitions

The Fix

Two fastboot commands after unlocking the bootloader. The modem rebuilds clean NV from the golden fsg partition.

fastboot 
# 1. Record IMEI first (dial *#06#)
fastboot erase modemst1
OKAY [  0.139s]

fastboot erase modemst2
OKAY [  0.005s]

fastboot reboot

# 2. Verify after boot
adb shell cat /sys/bus/msm_subsys/devices/subsys2/crash_count
0

adb shell getprop gsm.version.baseband
M6375_HI434_03.562.01.121R

Critical Prerequisites — Read These First

  • Unlockable bootloader — Motorola only unlocks retail units (XT2363-9 is retail). fastboot erase is refused while locked.
  • Record IMEI first — dial *#06# and write both numbers down. The erase wipes the NV store holding IMEI.
  • Backup before unlock — unlocking wipes /data (WhatsApp keys, 2FA seeds, everything). See backup guide.
  • Do NOT relock — relocking a modified boot chain bricks the device.

FAQ

Quick answers — full details in the GitHub FAQ.

Will this fix survive OTA updates?
Yes. OTA updates rewrite AP partitions (boot, dtbo, vendor_boot, super), not modemst1/2. The rebuilt NV persists.
Can I do this without unlocking the bootloader?
No. fastboot erase modemst1/modemst2 is explicitly refused while the bootloader is locked. Motorola's unlock is required (retail units only).
Is my IMEI at risk?
The erase wipes the NV store that holds the IMEI, but the modem rewrites it from the golden fsg partition on first boot. Record it first (*#06#) and verify after. Ours matched exactly.
Does a custom ROM (LineageOS, Pixel Experience, etc.) fix this?
No. Custom ROMs only replace AP partitions. They never touch modemst1/2. The modem firmware and its NV are separate.
Factory reset appeared to work for 3 hours — why?
Factory reset re-provisions the modem stack (rewrites /data/vendor/radio, clears telephony DB), which temporarily masks corrupt NV. But it never touches modemst1/2, so the corruption persists and the loop returns.
What is the qcrilNrd crash really?
A symptom, not the cause. The modem's QMI services vanish due to corrupt NV. Motorola's libmotext_inf.so then dereferences a token for a dead connection (-254 used as pointer) → SIGSEGV in qcrilNrd → system_server blocks → watchdog reboot.
Can I relock the bootloader after the fix?
No. Relocking with a modified boot chain (erased modemst1/2 = modified vendor state) will hard-brick the device. Leave it unlocked.
Is this fix specific to build V1UGS35H.75-14-9-3-1-4?
The root cause (corrupt modemst1/2) and fix (erase both) are build-agnostic for any fogos device. The exact baseband version may differ; verify gsm.version.baseband is present after reboot.
