The Problem

Your Moto G45 5G reboots every ~2 minutes. Factory resets and firmware flashes don't help. Understanding why is the first step to fixing it.

Symptom: The 2-Minute Bootloop

The phone boots normally, operates for ~2 minutes, then reboots. This cycle repeats indefinitely. Survives OTA updates, LMSA firmware flashes, and factory resets.

Why Standard Fixes Fail

  • OTA/LMSA flashes never touch modemst1/2
  • Factory reset only masks it for ~3 hours
  • Disabling apps reduces crash rate but doesn't fix the modem
  • Custom ROMs can't fix it — they don't touch modem partitions

The Crash Fingerprint

Every reboot generates a qcrilNrd crash with SIGSEGV at 0xffffffffffffff02 (-254 used as a pointer). Definitive signature of corrupt modem NV.

Root Cause Analysis

Two processors, one broken communication channel.

The device contains two independent computers: the Application Processor (AP) running Android, and the Modem/Baseband handling radio, SIM, calls, and data. They communicate over Qualcomm's OEM Hook channel, brokered by RIL daemon qcrilNrd.

The Failure Chain

  1. Corrupt NV Database: Modem's non-volatile memory (modemst1/modemst2) is corrupted — modem asserts on every boot.
  2. QMI Services Vanish: Modem QMI services never come up — communication channel goes silent.
  3. Dead Token Dereference: Motorola's libmotext_inf.so uses a token for a dead connection (-254 as pointer).
  4. SIGSEGV in qcrilNrd: Invalid memory access crashes the RIL daemon.
  5. System Server Blocks: system_server waits on a Binder call that never returns.
  6. Watchdog Reboot: After ~60s, hardware watchdog forces reboot. Cycle repeats every 2 minutes.
Key insight: The qcrilNrd crash is a symptom, not the cause. Erasing modemst1/2 lets the modem rebuild NV from the pristine fsg partition.

Prerequisites

This is not a phone-only repair. You need a PC, a data cable, and preparation.

Critical Requirements — Read Before Starting
  • Unlockable bootloader — Motorola only unlocks retail units (XT2363-9 is retail). fastboot erase is refused while locked.
  • Record IMEI first — Dial *#06# and write both numbers down. The erase wipes the NV store holding IMEI.
  • Full backup before unlock — Unlocking wipes /data (WhatsApp keys, 2FA seeds, everything).
  • Do NOT relock — Relocking a modified boot chain will hard-brick the device.

Hardware & Environment

  • Windows 10/11 PC with admin rights
  • USB data cable — not charge-only
  • Direct USB port — no hubs or docks
  • 30–60 GB free disk space

Software Setup

  • Android SDK Platform-Tools (ADB + Fastboot)
  • Motorola LMSA / Rescue and Smart Assistant
  • Internet on PC for unlock code & firmware

Phone Configuration

  • USB Debugging enabled + "Always allow from this computer"
  • Screen lock set to None temporarily
  • Battery > 50%
  • Google account password known (FRP)

The Fix Procedure

Seven precise steps. Follow them in order. Do not skip verification.

1

Back Up All Data

Unlocking performs a factory reset, permanently deleting everything in /data — including WhatsApp keys, authenticator seeds, and personal files.

Backup Guide
2

Confirm This Is Your Bug

Verify: 2-minute reboot cycle with qcrilNrd SIGSEGV at 0xffffffffffffff02 in logcat -b crash.

3

Record IMEI

Dial *#06# and write down both IMEI numbers. The erase wipes NV storing IMEI; modem rewrites it from fsg on first boot — verify after.

4

Unlock the Bootloader

Use Motorola's official unlock portal (motorola-global-portal.custhelp.com). Requires Motorola account, wipes device, only works on retail units.

5

Erase Modem NV Partitions

Boot into fastboot mode (Power + Volume Down), then run:

# Erase both modem NV partitions
fastboot erase modemst1
OKAY [  0.139s]

fastboot erase modemst2
OKAY [  0.005s]

# Reboot — modem rebuilds NV from golden fsg partition
fastboot reboot

The modem automatically reconstructs a clean NV database from the pristine fsg partition on first boot. This is the actual fix.

6

Verify Modem Stability

After boot (first boot may take several minutes), run:

# 1. Modem crash counter must be 0
adb shell cat /sys/bus/msm_subsys/devices/subsys2/crash_count
0

# 2. Baseband must be present
adb shell getprop gsm.version.baseband
M6375_HI434_03.562.01.121R

# 3. SIM state must be LOADED
adb shell getprop gsm.sim.state
LOADED
7

Confirm IMEI & Monitor

Dial *#06# — both IMEIs must match your recorded numbers. Then monitor uptime for 30+ minutes, then perform one manual reboot to confirm persistence. A single clean boot is not proof.

Success criteria: Zero modem crashes, baseband present, SIM LOADED, IMEI intact, LTE data & voice working, 2+ hours uptime, survives reboot.

Frequently Asked Questions

Will this fix survive OTA updates?
Yes. OTAs rewrite AP partitions (boot, dtbo, vendor_boot, super), not modemst1/2. The rebuilt NV persists.
Can I do this without unlocking the bootloader?
No. fastboot erase modemst1/modemst2 is refused while locked. Motorola's official unlock is required.
Is my IMEI at risk?
The erase wipes the NV store holding IMEI, but modem rewrites it from fsg on first boot. Record it first (*#06#) and verify.
Does a custom ROM fix this?
No. Custom ROMs only replace AP partitions — never touch modemst1/2. Modem firmware and NV are separate from Android OS.
Factory reset appeared to work for 3 hours — why?
Factory reset re-provisions the modem stack, temporarily masking corrupt NV. It never touches modemst1/2, so the loop returns.
Can I relock the bootloader after the fix?
No. Relocking with a modified boot chain will hard-brick the device. Leave it unlocked.
